# 実サーバーでエージェントを一周させるゲート(未実施)

**このリポジトリで唯一まだ通っていない検証**である。UI も状態機械も契約もそこにあるが、
**実サーバーで推論が走ったことが一度も無い**ため、以下は実物で観測できていない
(`HANDOFF.md`「402 / モデル未解決で推論が走らない」):

- `question.asked` / `todo.updated` の発火
- revert が実際にファイルを巻き戻すこと(往復は 200 で測れたが、巻き戻す対象が生まれない)
- assistant メッセージの `cost` / `tokens` の実値
- 空でない `GET /permission` / `GET /session/{id}/diff`

**推論を伴わない口は全部測れている。** 足りないのは推論そのものである。

## 前提: プロバイダのキー(**利用者が入れる**)

`opencode serve` を動かすホストに、**動くプロバイダを1つ**用意する。安いモデルで足りる。
キーの投入は serve 側の設定作業であり、**このリポジトリにキーを置かない**
(`.env` は `.gitignore` 済み。`6cd37cc` の経緯を参照)。

投入できたことの確認:

```
curl -u opencode:<pass> http://127.0.0.1:4097/provider | ...   # 使えるモデルが並ぶ
```

**注意**: `GET /provider` は接続済みプロバイダの API キーを平文で返す(実測)。
応答をそのままログや証跡に貼らないこと。アプリ側のガードは実装・実測済みだが、
**手で撃った curl の出力はガードの外**である。

## ゲートの順序(1つでも落ちたら止める)

前段の各ゲートと同じ規則: **測る前にビルドして `install -r`、`pm path` で引き戻してハッシュ照合**。
`adb` は `-s emulator-5570`(このプロジェクト専用。`ENVIRONMENT.md`)で固定する。

| # | 操作 | 何が読めれば合格か |
|---|---|---|
| 1 | セッションを作り、ファイルを1つ書き換える指示を送る | `session.status` が busy になり、本文が逐次描画される。`chat-model-pill` が実モデルを指す |
| 2 | ツール実行が始まる | ツールカードが running → completed。**同一 `part.id` のまま**更新される(P3 の欠陥形) |
| 3 | 書き込みの permission が出る | `permission-card:*` が dump に出て、**承認すると閉じる**(P4 の欠陥形 #2/#3 の現場) |
| 4 | エージェントが todo を立てる | `todo-*` が出る。**実物での発火はこれが初observation** |
| 5 | 質問を返してくるまで待つか、曖昧な指示で誘発する | `question-card:*`。同上、実物では初 |
| 6 | 完了後に差分を見る | `GET /session/{id}/diff` が**空でない**。差分画面が実データを描く |
| 7 | 巻き戻す | **ファイルが実際に戻る**。ホスト側で `git status` を撃って確かめる |
| 8 | コストを見る | assistant メッセージの `cost` / `tokens` が**実値**。Q10 のコスト表示が実データで動く |

## 予想される落ち方(先に書いておく)

このリポジトリでは**契約の食い違いが実測に7件覆されている**。推論経路だけが例外である
理由は無い。特に危ないのは:

- **`question.asked` / `todo.updated` の DTO の形**。P4 では `metadata` を `String?` と
  宣言してダイアログが一度も出ず、**フィクスチャ自身が誤った形を流していたので気付けなかった**。
  同じ構図がここに残っている可能性が高い(スタブしか流していない)
- **未宣言のフィールドで配列全体がデコード失敗する形**。Q10 で3回起きた
- **`cost` / `tokens` の型**。spec の宣言と実物のズレは既に何度も出ている

落ちたら**スタブを実測に合わせる**(スタブを正にしない。欠陥形 #9)。
